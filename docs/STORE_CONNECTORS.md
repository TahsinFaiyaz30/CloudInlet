# Microsoft Store connector delivery

CloudInlet is a full-trust WinUI 3/.NET 8 desktop app for x64 PCs. Its cloud backup and file transfer engine acquires signed storage adapters after installation. The same Connectors page works in each edition. Store servicing updates the host executable. Each connector uses a separate reviewed subscription. The base MSIX carries the shared SDK and a public catalog pin and starts with zero transport implementations.

## Policy assessment

Microsoft Store Policies version 7.20, reviewed 25 November 2026, §10.1.5 permits user-consented acquisition of extensions that enhance a product after initial download. It separately addresses acquisition of other products. Section 10.2.2 restricts dynamic code that fundamentally changes the described functionality or introduces policy violations. Sections 10.2.3 and 10.2.4 address security and disclosure of required dependencies. Our interpretation is that user-selected storage adapters serving CloudInlet's advertised backup and transfer functions fit this extension provision. Certification of this specific use remains a Microsoft decision. [Microsoft Store Policies](https://learn.microsoft.com/en-us/windows/apps/publish/store-policies)

The install dialog shows the exact publisher, fingerprint, source, capabilities, versions, and dependencies before code acquisition. Independent publishers can distribute signed storage connectors or supply a private signed file. Their code executes with the user's full-trust process rights, including access to user files, credentials and the network. A signature authenticates the publisher and inventory. A user must trust the publisher's code. New subscriptions and new required dependencies receive separate review. Automatic updates require opt-in and preserve publisher and source.

MSIX writes archives, registry and staging files under `ApplicationData.Current.LocalFolder\ProviderPacks\<flavor>`. Windows manages the package-local directory. The application installation directory remains read-only. The desktop editions use their per-user CloudInlet directory. Jobs and account credentials have their existing stores. Removing a pack removes its executable code while preserving accounts and recovery metadata. [Packaged desktop app storage](https://learn.microsoft.com/en-us/windows/msix/desktop/desktop-to-uwp-behind-the-scenes)

## Certification material for a future app submission

Suggested first listing sentence: “CloudInlet downloads the storage connector you select before connecting to Backblaze B2 or OneDrive. An internet connection and an account with the selected provider are required for cloud operations.”

Describe the Connectors page, private connector trust prompt, free downloads, and optional source-specific automatic updates in the listing. Explain the access of provider code in the privacy documentation. For certification, provide an isolated test account through Partner Center's private certification notes and verify both catalog and immutable assets are reachable. Ask the reviewer to install one provider, check the displayed publisher and source, disable and remove it, and verify that the other provider stays available for separate download. An in-progress transfer should pause with **Install required connectors** if its provider is missing. A newly enabled connector can then resume the preserved job. Product identity and Windows folder integration retain their existing contracts. [Store testability and disclosure requirements](https://learn.microsoft.com/en-us/windows/apps/publish/store-policies)

## Optional MSIX packages and contingency

There are no Store connector product IDs or separately approved optional packages configured for these two extensions. An executable Store optional package would require Microsoft permission and related-set authoring and servicing. Microsoft's example covers .NET Native and needs separate validation for WinUI 3/.NET 8. Related-set servicing can bind versions. Microsoft documents different-publisher related sets for deployment outside the Store. A Partner Center add-on or the product's existing virtualization permission does not establish executable-package approval. [Executable optional packages](https://learn.microsoft.com/en-us/windows/msix/package/optional-packages-with-executable-code) · [Related sets](https://learn.microsoft.com/en-us/windows/msix/package/optional-packages) · [Windows extensibility options](https://learn.microsoft.com/en-us/windows/apps/develop/launch/extensibility-overview)

Confirm the acquisition, servicing and upgrade behavior with real reserved identities before releasing that alternative.
